# Fork maintenance

- This is a fork of `end-4/dots-hyprland`. Preserve upstream history, licensing, and attribution.
- Keep custom additions limited to Hyprland, Quickshell, and related desktop component configuration (terminal, input method, portals, themes, and matching login interfaces), plus the tools, tests, and documentation directly needed to maintain them. Privileged PAM adapters and system installation remain outside the fork.
- The user removed greetd and its dedicated Quickshell login interface. Do not restore their files or build/test tooling. Desktop locking remains in Quickshell.
- The SDDM theme now provides password-only login. Do not reintroduce fingerprint icons, empty-password fingerprint state or silent fingerprint failure handling in this theme. System PAM configuration remains outside the fork.
- Keep `DesktopLock` directly under `ShellRoot`, outside settings-gated desktop panel loaders. Restore its in-memory lock state before transferring the Wayland lock, restart authentication after reload, and defer lock style replacement until normal unlock. Never unlock from a destruction handler.
- Keep machine administration outside this repository: boot loaders, Secure Boot/TPM, disks and snapshots, global PAM/account changes, package cleanup procedures, and other desktop environments. Maintain those tools and notes locally outside Git. Authorization to configure this machine is not authorization to add that work to this fork.
- The checkout is the source of truth for the maintained desktop configuration. Edit `dots/`, then deploy the curated changes with `python3 tools/desktop-config.py deploy`.
- Add new customized desktop files to `config/managed-files.txt`; keep `config/scrolling-profile.json` limited to shareable interface preferences.
- Keep runtime state, credentials, generated theme colors, monitor arrangements, design backups, and screenshots on the local machine.
- Settings > Interface > Desktop layout selects `desktopLayout`: `scrolling` (default) or `classic` (original fork's dwindle). Switch layout, workspace management, bar, overview, bindings and gestures together. Keep existing windows/workspaces; do not reset the selected mode on deploy. Disable dynamic workspace mutations and cancel pending scrolling placements outside scrolling mode. Read the persisted enum on native configuration load; reload only after settings writes finish.
- Keep bar and overview preferences in independent `desktopLayouts.classic` / `desktopLayouts.scrolling` profiles. Migrate legacy shared values once; never overwrite either profile on deployment. Settings edits the requested mode; live surfaces follow the successfully applied native mode. Keep native layout geometry and gestures in `custom/layouts/classic.lua` and `custom/layouts/scrolling.lua`. On returning from tiling, adopt current workspace monitor ownership instead of restoring stale scrolling homes. Wallpaper, theme, input devices and input methods remain shared.
- In scrolling mode preserve per-monitor dynamic workspaces, unified Win/Win+Space overview, simple rounded previews, and animated centered window ribbon. Clicking a ribbon icon must preserve the cursor position. Standard keyboard focus keeps its normal warp behavior.
- Hovering a partially visible column must not move the scrolling viewport. Keep `scrolling:follow_focus = true` for explicit navigation and `scrolling:follow_min_visible = 1.0` to suppress hover-driven panning.
- Numbered workspace shortcuts and Win+Tab are intentionally removed in scrolling mode; classic mode restores the original bindings. Do not add workarounds for the external keyboard's dropped Win+left-Shift+Right chord.
- The user chose Win+R for coordinated column layouts: halves, wide-left/narrow-right, narrow-left/wide-right, then three equal columns. Keep the original focused window. With only two columns, skip the three-column preset. Win+Semicolon and Win+Apostrophe independently select the current column's previous/next configured width (`colresize -conf/+conf`), with key repeat enabled.
- Shortcut cleanup must use the actual pre-scrolling user configuration, not upstream alone: `~/Projects/hypr-scroll-design/backup-20261002-011435/.config/hypr/custom/keybinds.lua` is the original local backup. All eight XF86Back/XF86Forward combinations with Super, Ctrl+Super, Super+Shift, and Super+Alt are longstanding user bindings and must be preserved. Distinguish new combinations from existing keys whose actions were adapted to scrolling; only remove confirmed redundant additions.
- Run every `node tests/*.cjs` script, `python3 -m unittest discover -s tests -p 'test_*.py'`, and `git diff --check` for configuration maintenance. Use actual Hyprland session checks when changing interactive behavior.
- Keep `origin` on the personal fork and `upstream` on the original repository. Merge upstream changes without discarding the fork's commits.
